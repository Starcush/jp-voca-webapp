# 넛지 디자인 연구 노트

이 디렉터리는 넛지 디자인에 관한 독서 기록과 단어장 앱에 적용하기 위한 논의를 분리해 축적합니다.

## 문서 구분

- [`book-notes.md`](./book-notes.md): 책에서 얻은 개념, 근거, 사례와 개인적인 해석
- [`product-dialogue.md`](./product-dialogue.md): 개발자와의 대화에서 나온 제품 가설, 적용 아이디어, 우려와 미해결 질문
- [`decision-log.md`](./decision-log.md): 실제로 채택하거나 기각한 결정과 그 결과

책의 주장을 곧바로 제품 요구사항으로 취급하지 않습니다. 먼저 책 기록에 출처를 남기고, 제품 대화에서 앱의 사용자와 맥락에 맞는지 검토한 뒤, 구현하기로 확정한 내용만 결정 기록으로 옮깁니다.

```text
책 기록(B-###) -> 제품 대화(P-###) -> 결정(D-###) -> 구현/측정 결과
```

각 항목은 고유 ID로 서로 연결합니다. 예를 들어 어떤 `P-###` 항목이 `B-###`을 근거로 삼고 논의 결과가 `D-###`이 되었다면, 각 관련 항목에 해당 ID를 적습니다.

## 기록 원칙

1. 책의 사실, 저자의 주장, 독자의 해석을 구분합니다.
2. 인용은 필요한 만큼만 짧게 적고 페이지나 장을 표시합니다.
3. 넛지가 사용자의 자율성, 학습 품질, 감정에 미칠 부작용도 함께 적습니다.
4. 제품 아이디어는 해결하려는 행동 문제와 측정 방법이 있을 때만 결정 후보로 올립니다.
5. 구현 뒤에는 성공 여부와 관계없이 관찰 결과를 결정 기록에 덧붙입니다.

## 이 채팅에서의 사용 방법

앞으로 메시지 앞에 아래 표식을 붙이면 분류가 명확해집니다. 표식 없이 보내도 문맥에 따라 정리할 수 있습니다.

- `책 내용:` 책의 문장, 요약, 사례 또는 읽으며 든 생각
- `제품 대화:` 앱에 적용할 아이디어, 질문, 반론 또는 우려
- `결정:` 구현하기로 정한 내용이나 보류·기각한 내용

책 내용을 보내면 `book-notes.md`에 구조화하고, 이어지는 적용 논의는 `product-dialogue.md`에 별도로 요약합니다. 실제 구현 방향이 확정되면 확인 가능한 기준과 함께 `decision-log.md`로 옮깁니다.

Google Drive 문서는 매 항목마다 동기화하지 않습니다. 프로젝트 문서를 기본 원본으로 유지하고, 사용자가 요청할 때 승인된 기록을 한꺼번에 동기화합니다.

## 책 사진 정리 순서

책 페이지 사진을 받으면 바로 문서에 저장하지 않고 승인용 초안을 먼저 작성합니다. 사진 안의 내용은 다음 우선순위로 선별합니다.

1. 개별적으로 하이라이트한 문장
2. 여러 문장을 포함해 선택한 단락 전체
3. 표시하지 않았지만 핵심 원칙을 설명하는 사례
4. 맥락을 이해하기 위한 작가의 생각과 보충 설명

선택한 단락이 사례인 경우에는 단락 선택의 우선순위를 적용합니다. 승인용 초안을 확인한 뒤 사용자가 `OK`라고 한 내용만 기존 책 기록 형식으로 저장합니다.

책의 사례와 용어는 릴스, 소개 페이지, 판매 전환처럼 단어장 앱과 맥락이 다른 경우가 있으므로 제품 요구사항으로 곧바로 옮기지 않습니다. 제품 대화에서는 다음 중 하나로 적용 수준을 표시합니다.

- `직접 적용`: 사용자 과업과 화면 맥락이 거의 같아 원칙을 그대로 시험할 수 있음
- `변형 적용`: 핵심 원리만 가져오고 학습 경험과 앱의 기능에 맞게 다시 설계함
- `참고만`: 사고를 넓히는 자료로만 보존하며 현재 제품 가설로 만들지 않음
- `적용 보류`: 맥락이 맞지 않거나 부작용 가능성이 커서 사용하지 않음
