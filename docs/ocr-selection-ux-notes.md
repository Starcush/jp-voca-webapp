# OCR 선택 UX 문제 정리

## 배경

현재 OCR 가져오기 기능은 사진에서 텍스트를 추출하고, 추출된 문장을 기준으로 사용자가 모르는 단어/표현을 선택해 단어장에 추가하는 흐름이다.

문장 추출 자체는 어느 정도 사용할 수 있는 상태지만, 그 다음 단계인 "사용자가 어떤 단어/표현을 고르는가"의 UX가 아직 직관적이지 않다는 피드백이 있었다.

## 현재 문제

- OCR 추출 후 문장 단위로 넘어가는 것까지는 비교적 이해된다.
- 그러나 그 다음에 사용자가 문장 안에서 직접 드래그해야 한다는 점이 처음 보는 사람에게 명확하지 않다.
- "문장에서 단어를 드래그하세요"라고 설명해도, 실제로 무엇을 해야 하는지 바로 감이 오지 않을 수 있다.
- Android에서는 네이티브 텍스트 선택 동작이 iOS/데스크탑과 달라 선택 인식이 불안정했다.
- 문장 수정 UI도 기본 흐름에 비해 무겁고, 단어를 담으려는 사용자에게는 방해처럼 느껴질 수 있다.
- 사진 속 글자를 보고 선택하고 싶다는 기대와, 현재 앱에서 추출된 텍스트를 다시 드래그해야 하는 경험 사이에 간극이 있다.

## 외부 피드백

대화에서 받은 주요 피드백은 다음과 같다.

- 드래그하는 것이 직관적이지 않다.
- 문장으로 완성되는 것까지는 이해가 잘 된다.
- 드래그를 설명해도 어려울 것 같다.
- 사용자는 사진/갤러리/맥북에서 글자를 드래그하고 하이라이트하는 경험에 익숙하다.
- 그래서 사진에서 직접 글자를 찾고 하이라이트해서 선택하는 방식이면 더 쉽게 느껴질 수 있다.
- 하이라이트가 되는지 여부가 중요한 문제일 수 있다.

## 사용자 고민

- 사진에서 직접 드래그하는 방식은 직관적일 수 있다.
- 다만 책 사진의 글자는 모바일에서 너무 작아서 보기 어렵다.
- 사진 위에서 선택하려면 확대, 좌표 매핑, OCR 박스 정렬 등이 필요해 보인다.
- 현재처럼 OCR 문장으로 쪼개는 방식은 꽤 괜찮다고 느낀다.
- 그러나 현재 문장 수정 UX와 문장 내 선택 UX가 충분히 편한지는 의문이다.
- OCR과 문장/단어 선택은 문장 분석 기능만큼이나 서비스의 큰 축이 될 수 있으므로, 처음 봐도 이해되는 플로우가 필요하다.

## 시도 1: 문장 카드 선택 후 큰 문장에서 드래그

첫 번째 개선 시도는 사진에서 추출된 문장들을 카드 목록으로 보여주고, 사용자가 문장 하나를 선택하면 아래 큰 문장 영역에서 표현을 드래그하는 방식이었다.

변경 내용:

- "문장별 선택" 중심 UI를 "사진에서 찾은 문장" 목록으로 변경
- 선택된 문장을 카드에서 강조
- 선택된 문장을 아래에 크게 표시
- 문장 수정 UI는 기본 접힘 상태로 변경
- 추가 예정 목록을 문장 선택 아래에 배치

의도:

- 사진 속 문장을 고른다는 인상을 일부 주기
- 작은 사진 글씨 대신 큰 텍스트에서 선택하게 하기
- 문장 수정 UI를 보조 기능으로 낮추기

한계:

- 실제 사용자가 느끼기에는 기존과 크게 다르지 않았다.
- 여전히 "큰 텍스트를 드래그해서 선택"해야 한다.
- 사진/갤러리에서 글자를 하이라이트하는 인상은 충분히 주지 못했다.
- 드래그라는 행동 자체를 더 직관적으로 만들지는 못했다.

## 시도 2: 커스텀 하이라이트 선택 UI

두 번째 시도는 OS 기본 텍스트 선택을 쓰지 않고, 앱 자체에서 선택 가능한 토큰/글자 하이라이트 UI를 만드는 방식이다.

변경 내용:

- 큰 문장 영역을 일반 텍스트 선택 영역에서 커스텀 선택 영역으로 변경
- 일본어/중국어는 글자 단위에 가깝게 토큰화
- 영어는 단어, 공백, 문장부호 단위에 가깝게 토큰화
- 사용자가 손가락/마우스로 쓸면 해당 범위가 앱 내부 하이라이트로 표시
- 선택된 텍스트를 아래에 표시하고 `추가` 버튼으로 담을 수 있게 함
- Android/iOS의 네이티브 텍스트 선택 동작 차이에 덜 의존하도록 함

의도:

- 사용자가 "스윽 밀어서 하이라이트한다"는 인상을 받게 하기
- Android/iOS/Safari/Chrome의 기본 텍스트 선택 차이를 줄이기
- 단어뿐 아니라 문법 조각, 짧은 표현 선택에도 대응하기

아직 확인해야 할 점:

- 실제 모바일에서 손가락으로 쓸 때 충분히 자연스러운가
- 일본어 문장을 글자 단위로 선택하는 것이 너무 잘게 느껴지지 않는가
- 영어는 단어 단위 선택이 자연스러운가
- 선택 범위를 잘못 잡았을 때 취소/수정이 쉬운가
- 길게 선택할 때 스크롤과 충돌하지 않는가
- 사용자가 이 UI를 처음 봐도 "쓸어서 선택하면 된다"고 이해하는가

## 검토한 대안

### 사진 위 직접 선택

사진 위에 OCR 결과 영역을 하이라이트하고, 사용자가 사진 속 글자를 직접 탭하거나 드래그해서 선택하는 방식이다.

장점:

- 가장 직관적이다.
- 사용자가 실제로 찍은 사진과 선택 행동이 직접 연결된다.
- 사진/갤러리에서 글자를 선택하는 경험과 유사하다.

단점:

- OCR 결과의 좌표 데이터가 필요하다.
- 이미지 확대/축소/회전/크롭과 OCR 좌표를 맞춰야 한다.
- 책 사진이 기울어져 있거나 그림자, 세로쓰기, 줄 간격이 있으면 난이도가 올라간다.
- 모바일에서 사진 속 글자가 너무 작을 수 있다.
- 잘못 인식된 텍스트를 수정하기 어렵다.

현재 판단:

- 장기적으로 실험할 가치는 있지만, 바로 MVP 플로우로 넣기에는 구현 난이도와 불안정성이 크다.

### OCR 문장 텍스트 기반 선택

사진에서 직접 선택하지 않고, OCR로 정리된 문장을 큰 글씨로 보여주고 그 안에서 선택하게 하는 방식이다.

장점:

- 모바일에서 글자가 커서 읽기 쉽다.
- 문장 수정과 연결하기 쉽다.
- OCR 좌표 매핑 없이 구현할 수 있다.
- 단어/문법/표현 선택 플로우를 안정적으로 만들 수 있다.

단점:

- 사진 속 글자를 직접 고른다는 느낌은 약하다.
- 사용자는 사진을 찍었는데, 실제 선택은 텍스트 화면에서 다시 해야 한다.
- 기본 텍스트 드래그 방식이면 여전히 직관성이 부족할 수 있다.

현재 판단:

- 단기적으로는 이 방향이 가장 현실적이다.
- 다만 기본 텍스트 드래그보다 커스텀 하이라이트 선택 UI가 더 적합할 수 있다.

## 현재 권장 방향

단기적으로는 `시도 2: 커스텀 하이라이트 선택 UI`를 실제 모바일에서 테스트해본다.

확인 후 좋다면:

- 선택 UI의 안내 문구를 더 다듬는다.
- 선택 취소/다시 선택 동작을 명확히 한다.
- 선택된 범위의 시각적 스타일을 더 자연스럽게 만든다.
- 문장 수정은 계속 보조 기능으로 유지한다.

별로라면:

- 현재 브랜치의 UX 실험을 폐기한다.
- 기존 텍스트 드래그 방식으로 돌아가되 안내와 버튼 배치를 개선한다.
- 장기 실험으로 사진 위 OCR 좌표 하이라이트 방식을 별도 기획한다.

## 남은 질문

- 사용자는 "문장을 고르고 그 안에서 표현을 선택한다"는 흐름을 자연스럽게 이해하는가?
- "드래그"보다 "쓸어서 선택"이라는 표현이 더 적절한가?
- 문법 표현처럼 짧고 애매한 단위를 고를 때 커스텀 하이라이트가 도움이 되는가?
- 사진 위 직접 선택이 꼭 필요한가, 아니면 큰 텍스트 기반 선택으로 충분한가?
- OCR 가져오기 기능은 단어장 앱의 핵심 차별화 기능으로 볼 만큼 자주 쓰일 것인가?
