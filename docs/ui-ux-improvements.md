# UI/UX 개선 메모

앱을 사용하면서 고치고 싶은 부분을 간단히 적어두는 문서입니다.

## 메모

### [완료] 목록 화면 보기/필터 버튼 의미가 헷갈림

상세정보:

현재 목록 화면에 `"전체보기"`, `"한자 가리기"`, `"뜻 가리기"` 보기 버튼과 `"전체"`, `"모르는 것만"`, `"오래 안 본 것"` 필터 버튼이 따로 보인다.

그런데 `"전체보기"`와 `"전체"`가 각각 무엇을 의미하는지 직관적으로 구분하기 어렵다. 사용자는 둘 다 전체를 보여준다는 의미로 받아들일 수 있다.

또한 `"모르는 것만"`, `"오래 안 본 것"`은 단순 필터라기보다 학습 로직과 연결되는 기능에 가깝다. Anki에서 사용하는 FSRS 기반 spaced repetition 방식, 또는 TypeScript 구현체인 `ts-fsrs` 같은 라이브러리를 활용해서, 단순히 오래 안 본 단어를 보여주는 수준이 아니라 복습 우선순위를 정해주는 방향으로 개선할 수 있을지 검토하고 싶다.

완료 내용:

- 처리 커밋: `5359250 ui: 단어 목록 보기 토글 정리`
- 목록 화면의 상태 필터 `"전체"`, `"모르는 것만"`, `"오래 안 본 것"`을 제거했다.
- 카드 표시 토글은 노트 선택 행 오른쪽으로 옮기고, `"전체"`, `"한자만 보기"`, `"뜻만 보기"`로 의미를 명확히 했다.
- `"한자만 보기"`는 뜻을 가리고, `"뜻만 보기"`는 한자/후리가나를 가리도록 라벨과 동작을 맞췄다.

기존 개선 방향 후보:

- `"전체보기"`는 카드 표시 방식이라는 의미가 드러나도록 라벨을 바꾼다.
- `"전체"`는 필터 초기화/전체 단어라는 의미가 드러나도록 라벨을 바꾼다.
- 보기 모드와 필터 모드가 서로 다른 역할이라는 점이 UI에서 더 분명해야 한다.
- `"오래 안 본 것"`은 나중에 Anki FSRS/`ts-fsrs` 기반 복습 추천 로직과 연결하는 방향을 검토한다.

### 단어 카드의 체크/물음표 버튼 역할이 애매함

상세정보:

현재 목록의 단어 카드에는 체크 버튼과 물음표 버튼이 있다. 체크는 `알았어요`, 물음표는 `모르겠어요`에 가까운 역할이지만, 목록 화면에서 항상 보이니 카드 높이를 차지하고 의미도 조금 애매하다.

단어 목록은 기본적으로 저장된 단어를 훑어보는 화면이고, 학습 판정은 복습 화면의 역할에 더 가깝다. 다만 사용자가 `"한자 가리기"`나 `"뜻 가리기"` 상태로 목록을 보다가 "아, 이거 방금 몰랐다"라고 느낄 수 있으므로, 완전히 없애기보다는 `복습 필요` 같은 가벼운 표시 액션으로 바꾸는 방향이 더 자연스러울 수 있다.

개선 방향 후보:

- 목록 카드에서는 체크/물음표를 항상 노출하지 않는다.
- 카드 메뉴나 작은 액션으로 `복습 필요`만 표시할 수 있게 한다.
- `알았어요`/`모르겠어요` 판정은 복습 화면에서 주로 처리한다.
- 나중에 Anki FSRS/`ts-fsrs`를 도입하면 `복습 필요` 표시가 복습 우선순위나 due 상태에 반영되도록 검토한다.

### 목록 화면의 선택/삭제 기능 위치가 고민됨

상세정보:

현재 목록 화면에는 `"선택"` 버튼이 있고, 선택 모드로 들어가면 여러 단어를 삭제할 수 있다. 하지만 기본 목록 화면은 단어를 보고 학습하는 공간에 가까워서, 삭제 같은 관리 액션이 항상 접근 가능하면 화면이 복잡해지고 실수 위험도 커질 수 있다.

삭제는 단어 이동과 마찬가지로 관리/정리 성격이 강하다. 따라서 기본 목록에서는 선택/삭제를 숨기고, 정리 화면에서 `단어 이동`, `일괄 삭제`, `노트 변경` 같은 관리 작업을 맡기는 방향이 더 자연스러워 보인다.

다만 목록을 보다가 바로 잘못 추가한 단어를 발견하는 경우도 있으므로, 단일 카드의 `수정` 화면 안에서 삭제하거나, 카드 메뉴 안에 `삭제`를 넣는 방식은 검토할 수 있다.

개선 방향 후보:

- 기본 목록에서는 `"선택"` 버튼을 제거하거나 더 숨긴다.
- 여러 개 선택 후 삭제는 정리 화면에서 제공한다.
- 단일 단어 삭제는 수정 화면 또는 카드 메뉴에서 처리한다.
- 삭제는 반드시 확인 다이얼로그를 거치게 한다.

### 정리 탭에 노트 관리 기능이 필요함

상세정보:

정리 탭에서는 노트 추가, 노트 이름 수정, 노트 삭제를 할 수 있어야 한다. 지금은 목록 화면에서 노트 필터는 가능하지만, 노트를 본격적으로 관리하는 화면이 충분히 분리되어 있지 않다.

노트 관리는 단어 목록의 핵심 화면에 계속 노출되기보다는 정리 탭에서 처리하는 것이 더 자연스럽다. 사용자는 정리 탭에 들어왔을 때 "단어장을 관리한다"는 기대를 가지므로, 여기에서 새 노트를 만들고 이름을 바꾸고 삭제할 수 있어야 한다.

개선 방향 후보:

- 정리 탭 안에 `노트 관리` 섹션을 만든다.
- 새 노트 만들기, 이름 수정, 삭제를 한 곳에서 처리한다.
- 노트 삭제 시 노트 안의 단어를 어떻게 처리할지 명확히 안내한다.
- 삭제 확인은 시스템 `confirm()`보다 인앱 다이얼로그로 개선하는 방향을 검토한다.

### 정리 탭의 단어 이동 UX가 불편함

상세정보:

현재 단어 이동은 출발 노트와 도착 노트를 select로 고르고, 아래 단어 목록에서 체크해서 이동하는 방식이다. 기능은 동작하지만 사용성이 좋은 편은 아니다. 특히 모바일에서는 select가 길어지거나, 단어 목록이 조밀해서 어떤 단어를 옮기는지 확인하기 어렵다.

단어 이동은 "어떤 노트에서 어떤 단어를 골라 어디로 보낼지"가 핵심이므로, 출발/도착 노트 선택과 단어 선택 과정이 더 명확해야 한다.

개선 방향 후보:

- 출발 노트 선택, 단어 선택, 도착 노트 선택, 이동 확정을 단계적으로 분리한다.
- 모바일에서는 select 대신 노트 선택 리스트나 바텀시트 형태를 검토한다.
- 선택한 단어 개수와 이동 대상 노트를 화면 하단 고정 액션 영역에 보여준다.
- 검색 결과에서 선택한 단어가 필터 변경 후에도 어떻게 유지되는지 정책을 정한다.

### 정리 탭에 여러 단어 삭제 기능이 필요함

상세정보:

여러 단어를 삭제하는 기능은 기본 목록보다 정리 탭에 있는 것이 더 자연스럽다. 정리 탭은 관리 작업을 모아두는 화면이므로, 단어 이동뿐 아니라 일괄 삭제도 여기에서 처리할 수 있어야 한다.

삭제는 실수 비용이 큰 작업이므로, 선택한 단어 목록과 개수를 확인한 뒤 삭제하도록 해야 한다. 가능하면 삭제 직후 토스트를 보여주고, 나중에는 짧은 시간 안에 되돌리기까지 검토할 수 있다.

개선 방향 후보:

- 정리 탭에서 여러 단어 선택 후 삭제할 수 있게 한다.
- 삭제 전 선택한 단어 개수와 일부 단어명을 확인시킨다.
- 삭제 완료 후 토스트를 보여준다.
- 장기적으로는 `삭제 취소` 또는 휴지통 개념을 검토한다.

### 정리 탭의 정보 구조를 다시 잡아야 함

상세정보:

정리 탭은 앞으로 노트 관리, 단어 이동, 단어 삭제를 모두 담당하게 될 가능성이 높다. 이 기능들을 한 화면에 그대로 펼치면 복잡해질 수 있으므로, 사용자가 하고 싶은 작업을 먼저 고르는 구조가 필요하다.

모바일에서는 설정 페이지처럼 `노트 관리`, `단어 이동`, `단어 삭제` 같은 메뉴형 진입이 더 나을 수 있다. 데스크탑에서는 같은 기능을 한 페이지 안에 카드나 아코디언으로 배치해도 괜찮다.

개선 방향 후보:

- 모바일: `노트 관리`, `단어 이동`, `단어 삭제` 메뉴로 진입한다.
- 데스크탑: 관리 섹션들을 한 화면에 정리하되, 접힘/펼침을 검토한다.
- 각 기능의 완료 후에는 정리 탭 메인으로 돌아오거나 현재 작업 흐름을 유지한다.
- 단어 목록 화면과 정리 탭의 역할이 겹치지 않도록 한다.

### 설정 페이지 진입 방식을 정해야 함

상세정보:

앱에는 기본적으로 설정 페이지가 필요하다. 설정에는 언어 관리, 계정 정보, 로그아웃, 나중에는 크레딧/결제/알림 같은 기능이 들어갈 수 있다.

다만 설정을 하단 탭의 1차 메뉴로 넣을지, 목록 상단이나 사이드바 하단의 아이콘 버튼으로 둘지 결정이 필요하다. 현재 하단 탭은 `목록`, `가져오기`, `정리`, `복습` 네 가지 학습 흐름을 중심으로 잡혀 있어서, 설정까지 하단 탭에 넣으면 주요 학습 기능의 밀도가 떨어질 수 있다.

개선 방향 후보:

- 하단 탭은 학습 핵심 기능 4개로 유지하고, 설정은 상단 아이콘 또는 언어 메뉴 안에 둔다.
- 데스크탑에서는 사이드바 하단에 설정을 둔다.
- 모바일에서는 목록 상단에 설정 아이콘을 둘지, 언어 메뉴 안에 둘지 비교한다.
- 설정 페이지 안에서는 언어 관리, 계정, 로그아웃을 명확히 분리한다.

### 탭 전환 시 화면이 깨지는 문제가 있음

상세정보:

하단 탭이나 주요 메뉴를 눌러 화면을 전환할 때, 일부 화면에서 레이아웃이 깨지거나 잠깐 이상하게 보이는 문제가 발생한다. 이 문제는 단순한 디자인 취향이 아니라 기능적 안정성에 가까우므로 우선적으로 확인이 필요하다.

원인은 화면 전환 중 로딩 상태, 공통 레이아웃의 높이/여백, 모바일 하단 탭과 콘텐츠 영역의 겹침, 특정 페이지의 컴포넌트 폭/overflow 문제일 수 있다.

개선 방향 후보:

- 탭 전환 시 공통 로딩/전환 상태를 안정적으로 보여준다.
- 각 주요 페이지의 모바일/데스크탑 최소 높이와 하단 여백을 점검한다.
- 하단 탭이 있는 모바일에서 플로팅 버튼이나 긴 폼이 겹치지 않는지 확인한다.
- 화면 전환 직후 레이아웃이 흔들리는 페이지를 구체적으로 기록하고 하나씩 수정한다.

### 노트 개념이 조금 복잡하게 느껴짐

상세정보:

현재 앱에서 노트는 단어를 묶는 단위로 필요하지만, 사용자 입장에서는 노트 선택, 노트 관리, 노트 안에서 추가, 노트 간 이동 같은 개념이 조금 복잡하게 느껴질 수 있다.

노트를 반드시 써야 하는 기능처럼 보이면 첫 사용자가 부담을 느낄 수 있다. 반대로 노트를 너무 숨기면 책/교재 단위로 단어를 정리하고 싶은 사용자가 불편해질 수 있다.

개선 방향 후보:

- 처음에는 `전체`와 `미분류` 중심으로 단순하게 보이게 한다.
- 노트는 "필요하면 쓰는 단어장 묶음"처럼 가볍게 설명한다.
- 노트 관리와 노트 필터의 역할을 명확히 분리한다.
- 노트 안에서 단어를 추가하고 OCR을 진행하면 해당 노트에 저장된다는 흐름을 더 자연스럽게 보여준다.
